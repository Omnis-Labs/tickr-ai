# AI Coding Test（2026 更新版）

## 關於這份測驗

這份測驗不是要看你能不能產出可跑的程式碼——AI 工具已經讓這件事相對容易。我們想看的是：你面對**模糊、混亂、需要判斷**的問題時，如何與 AI 協作，並把一次性原型轉成可靠系統。

我們在意的幾件事：

- **評估紀律**：你怎麼知道自己做的系統是對的
- **系統性思考**：面對會失敗的真實資料時的分解能力
- **工程權衡**：對成本、延遲、可靠性的判斷
- **AI 協作品質**：你跟 AI 工具的互動能不能放大你的產出

## 題目

以下兩題，**請至少完成一題**，兩題都完成會顯著加分。

- 題目一：泛用瀏覽器自動化 Agent
- 題目二：SEC 10-K 財報 Item-level 結構化抽取

## 共通要求

1. **AI 輔助開發**：可使用任何你覺得有效的 AI coding 工具。我們在意的不是特定工具，而是你如何用 AI 協助思考、實作、評估與迭代。
2. **Git**：公開 repo，commit history 要能反映真實開發過程
3. **前端呈現**：每個繳交的題目都必須透過可公開存取的網站前端呈現。Zeabur（[https://zeabur.com/](https://zeabur.com/)）可以是部署選項之一，但不是硬性規定。請不要只提供 API；需附上我們可以在瀏覽器中操作或檢視系統的 URL
4. **Prompt 紀錄**：在 repo 根目錄建 `prompts/` 資料夾保存主要 prompt——我們會實際閱讀
5. **README**：如何執行、主要設計決策、AI 在哪些環節協助了你
6. **分析報告**：請分析實作運行的效能、成本、擴充性，以及你如何驗證正確性
7. 僅使用公開或自建的資料

## 題目一：泛用瀏覽器自動化 Agent

做一個接收**自然語言任務描述**的瀏覽器 agent，能在不同網站上可靠執行。除了基本執行，agent 需要展現：

- **自我糾錯**：失敗時能診斷原因並嘗試不同策略
- **自我維護**：UI 或 selector 變動時能偵測並動態調整

自建一組 evaluation set 測試它的可靠性（涵蓋不同網域與任務類型），並提供可接收任務、顯示執行進度與結果、讓失敗案例可被檢查的網站前端。我們會用自己設計的任務驗證它在未見過的情境下的表現。

請在 README 或前端中清楚列出：

- 目前支援哪些網站，以及每個網站可以進行哪些操作
- 目前哪些網站或任務類型仍有問題、不穩定，或尚未支援，並提供具體例子

**我們會看**：自我糾錯與自我維護的實質性（不是只做 try/except 重試）、evaluation set 的深度、silent failure 的防範，以及你對效能、成本、擴充性與正確性驗證的分析。

## 題目二：SEC 10-K 財報 Item-level 結構化抽取

美國上市公司每年向 SEC 提交的 10-K 年度報告有規範的結構（Part I–IV 底下的 Item 1–16），但實際檔案格式變異極大。

請做一個 pipeline：從原始的 10-K filing 抽取出各個 item，讓它們能被獨立取用。請自建 evaluation set 驗證系統的可靠性，並提供網站前端，讓我們可以提交或選擇 filings、檢視抽取出的 items，並理解抽取信心或失敗案例。我們會用自己挑的 filings 驗證。

請在 README 或前端中清楚列出：

- 你認為目前抽取得好的 filings 或公司，並提供例子
- 目前仍有困難、不穩定，或尚未支援的 filings 或公司，並提供具體失敗案例

**我們會看**：在格式變異下如何保持穩健、在沒有公開 ground truth 的情況下如何驗證自己、edge case 的處理、成本紀律，以及你對效能、擴充性與正確性驗證的分析。

## 我們怎麼評

繳交後，我們會用你 eval set 之外的資料跑 held-out 測試、閱讀你的 code、文件與 prompt 紀錄，並在面試中與你深入討論設計決策。

大致分三級：

- **A 級**：eval 設計有深度、系統能展現分層與權衡、效能／成本／擴充性分析具體、失敗模式誠實、prompt 紀錄看得出高品質的 AI 協作
- **B 級**：基本功能完整，但 eval 與分析偏表面
- **C 級**：只在 happy path 上能跑
