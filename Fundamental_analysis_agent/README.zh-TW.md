## 🧭 完整 agent 套件（T1–T35）— 原理與互動關係

原本只是兩個評估題（T1 瀏覽器 agent、T2 10-K 擷取器），後來長成一套
**35 個 agent 的美股研究套件**：24 個訊號／組合 agent + **11 個對照組（placebo）**。
深入地圖在 [docs/AGENTS.md](docs/AGENTS.md)；這裡是自足的摘要。

### 共用設計模式（每個策略 agent 都一樣）

```
股票代號 → 蒐集資料（以某個決策日為界，as-of）
        → LLM 從一個「小而固定的 DSL」中挑「一個」策略（它從不自由寫程式）
        → 對該規則做確定性、「無前視（lookahead-free）」的回測
        → 結果對比 買進持有 + 標普 500（SPY），附上誠實的注意事項
```

兩條不變量讓它可信：

1. **無前視執行** — 在第 *i* 根 K 棒「收盤」算出的訊號，在第 *i+1* 根的**開盤**執行；
   來自申報文件的資料以**申報／公布日**為界，而非事件日。LLM 永遠只看得到 as-of 資訊。
2. **「選擇 ≠ 執行」** — LLM 只從受限的選單中**選擇**（無法透過程式洩漏未來價格）；
   **執行**是純確定性的 Python。十一個對照組（T25–T35）就是證明：它們華麗的 LLM 敘事
   會被算出來，但被引擎**完全忽略**。

## 💰 每個 agent 實際賺的是什麼錢（以及什麼時候賠錢）

一個訊號要賺錢，必須真的「收割」到某種東西：**風險溢酬**（你因承擔風險而獲報酬）、
**行為異象**（人性偏誤造成的錯價 —— 會*隨著被套利而衰減*）、**資訊優勢**（有人知道得更多），
或**相對價值套利**。逐一替每個 agent 點名來源，是最誠實的檢驗 —— 也因此暴露出其中好幾個
「優勢」早已衰減、擁擠，或（對兩個對照組而言）**刻意不存在**。T1/T2 是工具不是交易者：
它們不賺市場的錢，只是降低蒐集資料的成本。

| # | 實際收割什麼 | 什麼情況／假設下賺錢 | 什麼情況下賠錢 |
|---|---|---|---|
| **T3** 基本面 | 價值／品質溢酬 + 緩慢的基本面錯價 | 便宜／優質股重評價，且以申報為依據的論點正確 | 基本面已被定價（效率）、價值陷阱、或論點過擬合／錯誤 |
| **T4** 技術面 | 趨勢／動能風險溢酬 + 短期自相關 | 盤勢有趨勢且能延續 | 震盪／均值回歸盤把它來回巴；反轉時動能崩潰；成本累積 |
| **T5** 集成 | 訊號分散（降變異）+ 衝突門控 | 兩條弱相關的腿一致**且**都正確 | 相關性錯誤（一起看錯）或組合策略過擬合 |
| **T6** 內部人 | 資訊不對稱 —— 內部人知道更多 | 跟隨真正預示上漲的*機會型*群聚買進 | 訊號公開 + 延遲 + 擁擠；許多買進無資訊量（10b5-1、薪酬）；賣出太雜故忽略 |
| **T7** 相對強弱 | 橫截面動能／產業領先 | 強者持續領先其產業 | 因子輪動與急反轉 —— 它就是動能，承擔動能崩潰風險 |
| **T8** 財報（PEAD） | 財報後反應不足漂移 —— 最穩健的異象 | 真正優於預期 + 上調財測後漂移延續 | 預期已定價（大型股）、「完美定價」利多出盡、漂移衰減、成本 |
| **T9** 法人（13F） | 聰明錢的技能外溢（抄好經理人） | 經理人的優勢撐過 **45 天申報延遲** | 持股已過時／已出場；只看得到多頭股票部位；基金清單存活者偏誤 —— 很薄，多半只是確認 |
| **T10** 組合配置 | 分散 + 風險控制溢酬（賺的是 Sharpe，不是原始報酬） | 標的可分散、且滾動波動能預測未來波動 | 危機時相關性飆升（最需要時分散失效）；波動目標在底部去槓桿 |
| **T11** 基本面趨勢 | 盈餘／營收動能異象 | 加速中的基本面尚未被定價 | 成長均值回歸、價值陷阱、季度 XBRL 延遲 |
| **T12** 季節性 | 日曆異象（月底、Sell-in-May）—— 薄且有爭議 | 該型態為真*且*能在樣本外存活（罕見） | 樣本內資料探勘；它在訊號弱時退回買進持有，正因優勢通常不存在 |
| **T13** 隔夜／跳空 | 隔夜報酬溢酬（隔夜偏正、盤中持平） | 隔夜漂移延續 | 每日來回交易成本通常吃掉**整個**優勢 —— agent 一開始就坦白 |
| **T14** 波動度 regime | 低波動異象／波動管理 Sharpe（Moreira–Muir） | 波動有持續性，故避開高波動期能提升 Sharpe | 錯過常緊貼波動飆升後的劇烈反彈；平靜多頭中只是輸買進持有一個成本 |
| **T15** 庫藏股 | 庫藏股異象（股數下降 → 超額報酬） | 市場低估的、持續性的*真實*回購 | 高點舉債回購、只是抵銷稀釋的回購、或已被定價；訊號慢 |
| **T16** 放空壓力 | 放空餘額情緒／軋空 + 規避擁擠空頭 | 順勢吃軋空，或閃開擁擠的空頭 | 放空*量*含造市避險（雜訊）；餘額過時／雙月；空頭常常是*對的* → 接落刀 |
| **T17** 基本面品質 | 品質溢酬（Piotroski F-score、應計、資產成長異象） | 偏向高獲利、低應計、低資產成長的股票 | 垃圾／低品質股反彈（景氣早段 risk-on）；這些溢酬自發表以來已衰減 |
| **T18** 公司事件 | 事件驅動：13D 行動派創造價值 + 規避紅旗 | 行動派漂移兌現／紅旗被正確閃開 | 行動派失敗、增發已被定價、一次性事件；申報日延遲 |
| **T19** 價格異象 | 行為偏誤（52 週高錨定、樂透需求、稅損） | 該偏誤在樣本外仍存在 | 自發表以來大量套利／衰減；動能崩潰與反轉風險 |
| **T20** VIX regime 閘門 | 波動期限結構 regime 溢酬（逆價差 → 未來報酬更差） | 在指數上避開最糟的波動期 | 在常緊貼波動飆升的急漲日抱現金（來回挨打）；指數鈍工具，對個股弱 |
| **T22** 國會交易 | *號稱*的政治資訊優勢 —— 老實說**近乎零** | 只在有薄弱的揭露後漂移時才行 | 公開 + 擁擠 + 最多延遲 45 天揭露，殺光任何優勢；免費資料覆蓋不全。接近對照組，且如此標示 |
| **T23** 配對交易 | 統計套利／相對價值均值回歸（市場中性） | 共整合的價差「回歸」快於「發散」 | 關係**斷裂**（結構性變化／併購）；借券 + 雙倍成本；被大量套利；任何市場方向都可能賠 |
| **T24** 財報傳染 | 產業內資訊傳遞（read-across） | 同業在自己公布前，隨龍頭的驚奇而漂移 | 同業個別因素主導；*競爭性* read-across 讓符號反轉；已被定價；視窗極短且衰減 |
| **T25** 金融占星 ⚠️ | **什麼都沒有。** 無經濟機制 | 只靠運氣／雜訊 | 在占星上任意的「空手日」放棄股票溢酬 + 付成本 —— 本來就設計如此 |
| **T26** 梅花易數 ⚠️ | **什麼都沒有。** 無經濟機制 | 只靠機率 | 虛無分布顯示：毫無價值的擇時，光靠股票溢酬的變異就能跑出 p95 Sharpe ≈ 0.94 —— 這正是重點：它是「尺」，不是策略 |
| **T27** 八字 ⚠️ | **什麼都沒有。** 無經濟機制 | 只靠運氣／選擇偏誤 | 對單一精選的 10 倍股做一次命盤，可能僥倖超過虛無門檻 —— 正因如此，誠實的衡量是*分布*而非單次 |
| **T28** 紫微斗數 ⚠️ | **什麼都沒有。** 無經濟機制 | 只靠運氣 | 套件中最繁複的占卜盤（十二宮、四化飛星）依然是 placebo —— 它的作用是「看起來頭頭是道」卻只跑出虛無分布內的 Sharpe |
| **T29** 四柱推命 ⚠️ | **什麼都沒有。** 無經濟機制 | 只靠運氣 | 日式十二運星／天中殺只是同一個死訊號的不同*敘事* —— 正好示範換個占卜流派只換了故事、換不出（虛無的）edge |
| **T30** 七政四餘 ⚠️ | **什麼都沒有。** 無經濟機制 | 只靠運氣 | 真實天文星曆披上命理外衣——天文為真，預測力為零 |
| **T31** 鐵板神數 ⚠️ | **什麼都沒有**（雙重） | 只靠運氣 | 祕傳系統被化約為確定性數術替身——placebo 疊在無法驗證之上 |
| **T32** 奇門遁甲 ⚠️ | **什麼都沒有。** | 只靠運氣 | 三式盤局化約為「當日值使門」查表——儀軌繁複、edge 為零 |
| **T33** 大六壬 ⚠️ | **什麼都沒有。** | 只靠運氣 | 用神五行對日主——同一套死數術、換個詞彙 |
| **T34** 太乙神數 ⚠️ | **什麼都沒有。** | 只靠運氣 | 由積年算主客算之勝負——帝王級排場、零訊號 |
| **T35** Jyotiṣa ⚠️ | **什麼都沒有。** | 只靠運氣 | 最可計算的對照組（精確 Vimśottarī 大運）——仍是 placebo；精確 ≠ 預測力 |

**扣掉一切之後的誠實結論：** 計入成本與發表後衰減，最*站得住腳*的成員是風險溢酬收割者
（**T10** 分散、**T14**/**T20** 波動擇時）以及少數存活最好的異象（**T8** PEAD、**T17** 品質、
**T15** 庫藏股）。資訊優勢類（**T9**、**T22**）最弱 —— 公開、延遲、擁擠。而**任何**回測 Sharpe
沒超過**對照組虛無分布（≈0.94，見下）**的 agent，無論故事說得多動聽，都該當成「與運氣無異」。

## 🎲 統計誠實：對照組與虛無分布

一套 24 個 agent、每個都有數個策略範本，會跑出數百次無前視回測。**多重檢定（multiple testing）**
保證其中幾個純靠運氣就會跑出漂亮的 Sharpe —— 這是整個專案最大的方法論風險。與其揮手帶過，
套件直接附上**兩個對照組 agent**，在已知**毫無經濟機制**的訊號上跑*完全相同*的無前視回測：

- **T25 — 金融占星**（水星逆行／月相／行星相位，用 `ephem` 離線計算；日曆日期不洩漏任何價格資訊，故比任何申報更「無前視」）。
- **T26 — 梅花易數**（從日期確定性起卦，驅動體用五行生剋的多／空手規則）。

兩者中，LLM 都寫出華麗的星盤／卦辭論點，引擎**完全忽略它** —— 這是套件「選擇 ≠ 執行」不變量的
終極測試。若對照組跑出高 Sharpe，那是**框架在漏水**（或你正看著選擇偏誤），不是星象靈驗。

**反轉 —— 占卜 agent 變成整套套件的顯著性檢定。** 因為梅花易起卦吃一個 `seed`，我們可以抽出
一整條**虛無分布**：12 檔 × 40 個 seed = **480 次毫無價值的回測**跑過同一個引擎。結果是窮人版的
White's Reality Check：

```
虛無 Sharpe（480 次對照抽樣）：p50 = 0.10   p90 = 0.78   p95 = 0.94   p99 = 1.11   max = 1.29
→ 一個真 agent 要 Sharpe ≥ 0.94 才能在 95% 信心下贏過「隨機卦象擇時」。
```

所以像 T20 VIX 閘門的 Sharpe **1.21** 不會照單全收 —— 對這條虛無分布量測，它落在 **p ≈ 0.004**
（顯著）；而一個 Sharpe 0.6 的 agent 無論故事多好，都**與運氣無異**。自己跑：

```bash
python -m task26_meihua.eval.null_distribution --seeds 40 --observe 1.21
# → 虛無分布百分位 + 任意觀測 Sharpe 的 p-value
```

對照組在各處都標記 `is_control`，UI 上以紫色 **PLACEBO** 橫幅渲染，永遠不會被誤認為可交易訊號。

### 全 11 個對照組的虛無帶（一個令人謙卑的結果）

套件現有 **11 個占卜對照組**，橫跨四大傳統——西洋占星（T25）、中華 易/命理/星命/三式/數術
（T26 梅花易・T27 八字・T28 紫微・T30 七政四餘・T31 鐵板・T32 奇門・T33 六壬・T34 太乙）、日本四柱推命
（T29）、吠陀 Jyotiṣa（T35）。每個都有固定的確定性擇時規則，故
[`tools/divination_null_band.py`](tools/divination_null_band.py) 可免費跑遍**全部**對照組於 12 檔面板，
匯集 Sharpe：

```
占卜對照組虛無帶（348 次抽樣，11 系統 × 12 檔）：
   p50 = 0.47   p90 = 1.33   p95 = 1.42   p99 = 1.72   max = 1.95
疊加——各真 agent 在其 eval 案例上之「中位數」單檔 Sharpe：
   T17 0.74  T18 0.79  T19 0.88  T20 1.11  T21 0.40  T22 0.47  T23 −0.54  T24 0.62
   對照組 p95 = 1.42  →  0 / 8 越過（但多數高於對照組中位數 0.47）
```

![占卜對照組虛無帶 — 真 agent vs 11 個 placebo 系統](docs/analysis/divination_null_band.svg)

*（在 [`/dashboard`](https://your-deployment.example.com/dashboard) 上也有互動版；以
`python -m tools.divination_null_band && python -m tools.render_null_band` 重新產生。）*

**請誠實地讀這個數字，因為它是整個 repo 最重要的數字。** 匯集後的對照組 p95 是 **1.42**——比上面
單一引擎的 0.94 *更高*——而**沒有任何一個**真 agent 的中位數單檔 Sharpe 越過它（最強的 T20 也只有 1.11）。
這**不是**因為占卜有效；而是因為在多頭行情、megacap 面板上，原始單檔 Sharpe 被**漲上去那些股票之股票溢酬**
主導——一個毫無價值的規則，只要剛好抱著 NVDA 走完 4 倍就能跑出 ~1.9 的 Sharpe。（用中位數正是為了讓單一
幸運標的無法挑高分數；若用 max 會讓好幾個「假性越過」。）這正是對照組要揭露的多重檢定／選擇偏誤陷阱：
*挑對標的，任何擇時規則都「找得到」alpha。* 這也正是為什麼整套以 **alpha vs SPY** 為準、而非原始 Sharpe，
且公平比較必須 like-for-like（同標的、市場相對）——注意對照組的 *alpha* p95 同樣被灌水到 +105%，所以那也
不是乾淨的門檻。真 agent **確實**越過的是對照組*中位數*（0.47）：它們贏過擲硬幣式的擇時，只是贏不過幸運的
尾端。對照組不討好真 agent——它們用一條殘酷而誠實的標準檢驗它們。自己跑：

```bash
python -m tools.divination_null_band --observe 1.21   # 完整虛無帶 + 任意 Sharpe 的 p-value
```

## 🔭 誠實的限制（評分前先讀）

1. **Task 1 評測小**（15 案例），逐次通過率因 Gemini 在 `temperature=0` 的隨機性而在 **11–14/15** 浮動。系統誠實回報區間，而非最佳一次。
2. **Task 2 L3 保守** —— 邊界 IoU 門檻緊；目前提供仲裁、非積極取代（刻意「不靜默覆寫」，但難案會被隔離而非由 L3 修好）。
3. **信心校準用合成標籤**（從評測基線規則化自舉）；ECE 0.056 不錯，但生產上應以約 20 個人工標註重新驗證。`labels.provenance.json` 旁存使其誠實。
4. **一個已知失敗案例**（MSFT FY2015 Item 8）—— iXBRL 前格式整段以引用併入；系統正確隔離而非捏造。
5. **Task 1 不處理 CAPTCHA / Cloudflare / 已驗證 session** —— 合規選擇；agent 一律升級求助。
6. **即時（非評測）job 用記憶體儲存** —— 後端重新部署後，進行中的 job ID 在檢查器會 404。路線圖第 2 週（Alembic + 持久化）處理。
7. **跨年一致性檢查**（PLAN §3.5 的第四個信心訊號 w₄）已設計未實作；需多年攝取 pipeline。
8. **隔離的 Task 2 擷取尚無人工複審佇列** —— 已標記但未可指派。路線圖第 7 週。
9. **策略 agent 大多是免費資料先行**（yfinance 個人用途授權；真實產品需 Polygon/Tiingo/Alpaca 等付費源），且新加的 agent 多數尚無 eval set；T9/T22 的資訊優勢偏弱、T22 國會資料免費覆蓋不全。每個 agent 都把這些限制寫在自己的 caveats 與上面的「實際賺什麼錢」表。
